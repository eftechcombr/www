On November 13, 2026, EF-TECH shipped two rapid patch updates for [eftechcombr/glpi](https://github.com/eftechcombr/glpi): **v12.0.1** (Helm chart `glpi-2.12.2`) and, right behind it, **v12.0.2** (Helm chart `glpi-2.12.3`). Together, they roll up **13 upstream security fixes** from the GLPI 12.0.x line and fix a long-standing CI/CD race condition in our container build pipeline.

If you are deploying or upgrading today, **go straight to GLPI `12.0.2` and Helm chart `2.12.3`**. It includes every fix from `12.0.1` plus five additional High-severity patches released upstream on November 12.

## Two releases in one day: what shipped and why

The sequence on November 13 went like this:

1. **v12.0.1 (`glpi-2.12.2`)** bumped our distribution from [GLPI 12.0.0](/en/blog/glpi-12-0-0/) to upstream `12.0.1`, synced Compose, `.env`, Helm, and documentation across the repository, and passed full validation. During the release run, however, the parallel Nginx workflow failed its first attempt because it tried to pull `php-fpm-12.0.1` before the PHP-FPM workflow had pushed it — and we noticed that upstream `12.0.2` had already landed on November 12.
2. **v12.0.2 (`glpi-2.12.3`)** followed immediately to pick up the `12.0.2` upstream security release and consolidate the Docker publishing pipeline so **PHP-FPM always builds and publishes before Nginx**.

## The CI/CD fix: eliminating the PHP-FPM → Nginx publish race

One of the best outcomes of shipping two patches back to back was catching and permanently fixing a subtle workflow bug.

In `eftechcombr/glpi`, the Nginx container (`docker/nginx/Dockerfile`) is an unprivileged image built in two stages:

1. **Stage 1 (`BUILD`)** starts from `eftechcombr/glpi:php-fpm-<VERSION>` to copy GLPI's static webroot (`/var/www/html`) and expected data layout (`/var/lib/glpi`).
2. **Stage 2** copies those files onto `nginxinc/nginx-unprivileged:1.31.7-alpine3.24-slim`.

Previously, `docker-publish-php-fpm.yaml` and `docker-publish-nginx.yaml` were both triggered independently on a GitHub release event and ran **in parallel**. When `v12.0.1` was published, the Nginx workflow reached its `FROM eftechcombr/glpi:php-fpm-12.0.1` step before the PHP-FPM workflow had finished its multi-arch build and push — so the first Nginx run failed with a missing manifest error. A manual retry succeeded once PHP-FPM finished, confirming the race was pre-existing in the parallel trigger design.

In **PR #221 (`v12.0.2`)**, we consolidated the Docker publishing pipeline so **PHP-FPM builds and publishes before Nginx runs**. That enforces the real dependency graph in CI, guarantees the Nginx multi-stage build always pulls a freshly pushed multi-arch `php-fpm-<VERSION>` manifest, and removes manual retries from future releases.

## How to install or upgrade

Both the Docker Hub images and the Helm chart are multi-architecture ready (`linux/amd64` and `linux/arm64`) and run unprivileged (`runAsNonRoot: true`). We recommend pulling and deploying **`12.0.2` / `2.12.3`** directly.

### 1. Docker images

Pull the recommended **`12.0.2`** images:

```bash
docker pull eftechcombr/glpi:php-fpm-12.0.2
docker pull eftechcombr/glpi:nginx-12.0.2
```

Equivalent version-first tags (`12.0.2-php-fpm` and `12.0.2-nginx`) are also published, and `latest` is refreshed to the newest build. If you need to pin specifically to `12.0.1` for staging parity, `eftechcombr/glpi:php-fpm-12.0.1` and `eftechcombr/glpi:nginx-12.0.1` (along with `12.0.1-php-fpm` / `12.0.1-nginx`) remain available.

If you run Docker Compose from source with `docker/docker-compose-build.yml`, make sure you back up your database and `/var/lib/glpi` volume first, then let `glpi-db-upgrade` run the schema migration before bringing up `php` and `nginx`.

### 2. Kubernetes via Helm Chart

Add or refresh the EF-TECH Helm repository and upgrade directly to chart **`2.12.3`** (which deploys GLPI **`12.0.2`**):

```bash
helm repo add eftech https://eftechcombr.github.io/glpi/
helm repo update
helm upgrade --install glpi eftech/glpi --version 2.12.3
```

If you are targeting `12.0.1` specifically, use `--version 2.12.2`. During `helm upgrade`, the chart's `post-upgrade` hooks automatically run `glpi-verify-dir`, `mariadb-timezone`, `glpi-db-upgrade` (`php bin/console database:update`), `glpi-db-configure`, and `glpi-cache-configure` before rolling out the updated PHP-FPM and Nginx Deployments.

> **Coming from GLPI 10.x or 11.x?** Take a full MariaDB dump and file backup first, verify plugin compatibility for GLPI 12, and check our [GLPI 12.0.0 migration guide](/en/blog/glpi-12-0-0/) before running the upgrade.
